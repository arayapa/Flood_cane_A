มี 2 ไฟล์ ใช้งานต่างกัน

| | เวอร์ชัน A (`flood_cane_A_online.html`) | เวอร์ชัน B (`flood_cane_B_offline.html`) |
|---|---|---|

ไฟล์ .gpkg และ .tif ของเวอร์ชัน B คำนวณในเครื่องผู้ใช้ ไม่ถูกส่งออกไปที่ไหน

## เวอร์ชัน B · ใช้งานได้ทันที

**ผู้ดูแล:** รันสคริปต์ GEE ชุด set2 แล้วส่งไฟล์เหล่านี้ให้ทีม (มีไฟล์ไหนส่งไฟล์นั้น)

- `flood_map_set2.tif` แผนที่น้ำท่วม
- `NDVI_2026_MM_set2.tif` ความเขียวของพืช (เลือกเดือนล่าสุด)
- `DEM_30m_set2.tif` ความสูงภูมิประเทศ

**น้อง ๆ ในทีม:**

1. ดับเบิลคลิกเปิด `flood_cane_B_offline.html` (ใช้ Chrome หรือ Edge)
2. ลากไฟล์ `.gpkg` ลงช่องที่ 1
3. ลากไฟล์ `.tif` ลงช่องที่ 2 ตามชนิด
4. ระบุช่วงวันที่ของข้อมูล (ปฏิทิน หรือ วัน/เดือน/ปี พ.ศ.)
5. กด **▶ เริ่มวิเคราะห์** แล้วกดดาวน์โหลดผลเป็น CSV ได้

รองรับไฟล์ภาพทั้งแบบ UTM (EPSG:32647/32648) และแบบองศา (EPSG:4326)
รองรับไฟล์ .gpkg ในระบบพิกัด 4326, UTM WGS84 และ Indian 1975 (24047/24048) สูงสุด 1,000 แปลง

## เวอร์ชัน A · ตั้งค่าครั้งแรก (ผู้ดูแลทำครั้งเดียว ประมาณ 30 นาที)

### 1. สร้างหน้าจอขออนุญาตล็อกอิน

1. เข้า https://console.cloud.google.com เลือกโปรเจกต์ `third-octagon-448507-n8`
2. เมนู **APIs & Services → OAuth consent screen**
   - ถ้าองค์กรใช้ Google Workspace เลือก **Internal** (เฉพาะคนในองค์กร)
   - ถ้าไม่ใช่ เลือก **External** แล้วเพิ่มอีเมลน้อง ๆ ในหัวข้อ **Test users** (ได้สูงสุด 100 คน)
3. ตั้งชื่อแอป เช่น "ระบบติดตามน้ำและอ้อย" แล้วบันทึก

### 2. เปิดเว็บด้วย GitHub Pages (ฟรี)

1. สร้าง repository ใหม่ใน https://github.com
2. อัปโหลดไฟล์ `flood_cane_A_online.html` แล้ว **เปลี่ยนชื่อเป็น `index.html`**
3. ไปที่ **Settings → Pages** เลือก Branch `main` โฟลเดอร์ `/ (root)` แล้วกด Save
4. รอ 1–2 นาที จะได้ลิงก์ เช่น `https://ชื่อผู้ใช้.github.io/ชื่อrepo/`

### 3. สร้าง Client ID

1. กลับไปที่ Cloud Console เมนู **APIs & Services → Credentials → Create credentials → OAuth client ID**
2. Application type: **Web application**
3. **Authorized JavaScript origins** ใส่ `https://ชื่อผู้ใช้.github.io` (ไม่ต้องมีชื่อ repo ต่อท้าย)
4. กด Create แล้วคัดลอก **Client ID** (ลงท้ายด้วย `.apps.googleusercontent.com`)
5. เปิดไฟล์ `index.html` ใน GitHub กดแก้ไข ค้นหาบรรทัด

   ```
   CLIENT_ID: "ใส่_OAUTH_CLIENT_ID.apps.googleusercontent.com",
   ```

   แทนที่ด้วย Client ID ที่คัดลอกมา แล้วกด Commit

### 4. ให้สิทธิ์น้อง ๆ ในทีม

ที่ Cloud Console เมนู **IAM & Admin → IAM → Grant access** ใส่อีเมลของแต่ละคน แล้วให้ Role:

- `Earth Engine Resource Viewer`
- `Service Usage Consumer`

เสร็จแล้วส่งลิงก์ GitHub Pages ให้ทีมใช้งานได้เลย

### วิธีใช้ (น้อง ๆ ในทีม)

1. เปิดลิงก์ กด **เข้าสู่ระบบด้วยบัญชี Google** (ครั้งแรกจะมีหน้าต่างให้กดอนุญาต)
2. ลากไฟล์ `.gpkg` ไม่เกิน 300 แปลง
3. เลือก **ช่วงปกติ** (ก่อนน้ำท่วม) และ **ช่วงที่ต้องการตรวจ** (อย่างน้อย 12 วัน)
4. กด **▶ เริ่มวิเคราะห์** รอ 1–3 นาที
5. แท็บ 🎋 อ้อย เลือกแปลงแล้วกด **แสดงกราฟ** เพื่อดูการเติบโตย้อนหลัง

## ข้อควรรู้

- **ความสูงอ้อย** ดาวเทียมฟรีวัดเป็นเมตรโดยตรงไม่ได้ ระบบแสดงดัชนีการเจริญเติบโต 0–100
  ถ้าในไฟล์ .gpkg มีคอลัมน์ความสูงที่วัดจริงอย่างน้อย 5 แปลง ระบบจะประมาณความสูงแปลงอื่นเป็นเมตร พร้อมบอกค่าความแม่นยำ
- **ลิขสิทธิ์ Earth Engine** ใช้ฟรีเฉพาะงานไม่แสวงหากำไร ถ้าเป็นงานของบริษัทหรือเชิงพาณิชย์ ต้องสมัครแบบเสียค่าใช้จ่ายผ่าน Google Cloud
  (เวอร์ชัน B ใช้ไฟล์ที่ส่งออกจาก Earth Engine จึงอยู่ภายใต้เงื่อนไขเดียวกัน)
- ผลทั้งหมดเป็นค่าประมาณจากดาวเทียม ควรยืนยันด้วยการลงพื้นที่
